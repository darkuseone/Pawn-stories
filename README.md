# Pawn stories — конвейер сборки роликов

Канал про находки и аукционы: человек купил на барахолке ерунду за двести
рублей, она оказалась редкостью и ушла за сорок тысяч.

Конвейер собирает из текстового сценария готовый ролик и весь комплект для
выкладки. Работает в GitHub Actions без человека, кроме одного шага —
подтверждения материала.

Задание, из которого всё выросло, и четырнадцать замеренных технических
правил лежат в [`docs/ЗАДАНИЕ-аукционный-канал.md`](docs/ЗАДАНИЕ-аукционный-канал.md).
**Читать обязательно перед правками**: половина решений в коде выглядит
странно, пока не знаешь, что стоит за каждым.

pipeline/render.py     элементарные операции ffmpeg

pipeline/overlays.py   генератор слоя искр (нужен разово)
pipeline/make_luts.py  генератор цветокоров (нужен разово)
pipeline/mock.py       синтетические материалы для отладки без ключей
pipeline/channel.py    журнал канала: защита от повторов между роликами
pipeline/youtube.py    заголовок, описание с главами, теги, превью

assets/luts/           8 цветокоров: 5 тёплых + 3 архивных

## Что настроить

1. **Секреты.** Settings → Secrets and variables → Actions → вкладка
   **Secrets** (не Variables — их значения видны в логах):
   `XAI_API_KEY`, `ELEVENLABS_API_KEY`, `PEXELS_API_KEY`, `PIXABAY_API_KEY`.
   `ELEVENLABS_VOICE_ID` не нужен: голос читается из спецификации ролика.

   Этап `material` работает и без единого ключа: четыре источника из семи
   открыты (Wikimedia, Met Museum, Library of Congress, archive.org). Без
   Pexels и Pixabay не будет только стокового видео.

2. **Музыка.** Положить свой `assets/music/bed.mp3`, см.
   [`assets/music/README.md`](assets/music/README.md). Пока файла нет,
   ролик собирается с одним голосом и пишет об этом в лог.

3. **Спецификация.** Скопировать `jobs/auction-01.example.json` в
   `jobs/auction-01.json` и заполнить. Поля с подчёркиванием — комментарии,
   код их пропускает.

## Порядок работы

```
Actions → Build video → Run workflow
```

| stage | что делает | тратит деньги |
|---|---|---|
| `material` | качает видео и фото, собирает листы отбора | нет |
| `assets` | озвучка + генерация картинок + материал | да |
| `render` | только монтаж из готового | нет |
| `auto` | всё подряд | да |

Правильный порядок для нового ролика:

1. `material` — посмотреть, что нашлось по запросам. Бесплатно, можно
   гонять сколько угодно, правя `footage_queries` и `archive_queries`.
2. Скачать артефакт **select-\<ролик\>**, посмотреть контактные листы,
   вписать номера негодного в `reject`.
3. `auto` — полная сборка.
4. Дальше правки монтажа гонять только через `render`: материал лежит в
   кэше, озвучка и генерация не повторяются.

## Отладка без ключей и без денег

Прогон в GitHub Actions — это десять минут даже на коротком ролике. Монтаж
проверяется локально за минуты на синтетическом материале:

```bash
python pipeline/mock.py  jobs/auction-test.json   # тишина, карточки, testsrc2
python pipeline/build.py jobs/auction-test.json
```

`mock.py` ничего не перезаписывает: настоящий материал, если он уже лежит на
месте, остаётся нетронутым.

**Проверять замером, а не глазом.** `build.py` в конце сам печатает длину
видео, длину звука и размер файла. Расхождение видео и звука больше
полусекунды — это перекрытие переходов, и вылезает оно молча: код возврата
ноль, лог чистый, а конец начитки срезан. Подробности в задании, пункты 3 и 4.

## Чем этот канал отличается от исходного проекта

Код снят с действующего проекта того же устройства — сонного исторического
канала. Ниже то, что переделано под находки и аукционы.

### Цвет теплее

Холодная синяя семья (`steel_blue`, `deep_navy`, `slate_ash`, `cold_teal`,
`blue_amber`) убрана целиком. Лавка древностей, дерево, латунь и ламповый
свет — это янтарь и медь, а не сталь.

| цветокор | характер | R−B на серой шкале |
|---|---|---|
| `warm_amber` | базовый янтарь | +16.6 |
| `oak_brass` | дуб и латунь | +20.9 |
| `lamp_glow` | ламповый свет, самый вечерний | +25.3 |
| `dust_gold` | пыльное золото, приглушённый | +10.8 |
| `copper_dusk` | медь на закате, самый насыщенный | +18.5 |

Архивная семья — `archive_sepia`, `archive_silver`, `archive_paper`. Она
тоже тёплая и разведена с основной не оттенком, а плотностью: насыщенность
в два-три раза ниже, контраст выше, картинка читается как отпечаток.

Плёночная база `film_look()` тоже перевёрнута: раньше тень уходила в синий
(правильно для сонного канала), теперь тень тёплая и холода нет нигде.

Таблицы считает `pipeline/make_luts.py` — каждый цветокор описан пятью
понятными числами, а не 4913 строками, которые нельзя править.

### Доля генерации — 30%

Не вкусовщина. Сюжет про находку — рассказ про **конкретный** предмет: вот
эта монета, вот этот сервиз. Генератор такую монету не найдёт, он её
нарисует, и рисунок выдаёт себя за фотографию реального предмета. Под
предмет идёт только настоящее; генерация закрывает общие планы, руки крупно,
интерьер лавки, атмосферу.

Держит пропорцию `MaterialMix` в `build.py`, считает по экранному **времени**,
а не по числу кадров, и выдерживает её на любом отрезке ролика, а не только
в среднем. Что вышло — печатается при каждой сборке:

```
генерация       29.0%     0.6 мин     6 кадров
архивное фото   46.3%     1.0 мин    10 кадров
сток видео      24.7%     0.5 мин     9 кадров
```

Крутится полем `generated_share` в `style_override`.

### Вступление — три минуты

`intro_footage_seconds: 180`. Быстрая перебивка: куски видео по 2–4 секунды
вперемешку с фотографиями по 3–7, у фотографий всегда скольжение или наезд.
Работает и без стокового видео — тогда это перебивка из одних фотографий.

### Темп быстрее

`base_duration_range: [4.2, 5.6]` против 5.4–7.2 у сонного канала.

### Язык

Канал англоязычный. На английском — всё, что видит и слышит зритель:
сценарий, промпты генерации, запросы к стокам и архивам, заголовок,
описание, главы, теги. Комментарии в коде остаются на русском: они
объясняют решения владельцу канала, а не зрителю.

## Чтобы канал не выглядел конвейерным

YouTube показывает соседние загрузки канала рядом, и зритель видит их
именно рядом. Канал, у которого все ролики на одно лицо, читается как
поток — и зрителем, и площадкой. Стиль ролика выпадает случайно, но
случайность без памяти регулярно даёт три похожих ролика подряд.

Память ведёт `pipeline/channel.py`, журнал лежит в `channel/log.json`.

```bash
python pipeline/channel.py list                 # что уже выходило
python pipeline/channel.py check jobs/x.json    # не повтор ли это
python pipeline/channel.py record jobs/x.json   # записать ПОСЛЕ выкладки
```

`build.py` читает журнал сам и выдаёт движку стиля списки «этого не брать».

| ось | как разводится |
|---|---|
| тема | сравнение значимых слов, порог пересечения 34% на 8 последних роликов |
| цветокор | 3 последних не повторяются |
| тип открытия | 2 последних |
| основной переход | 2 последних |
| вариант искр | 2 последних |
| длина вступления | выпадает из 150–215 с, а не стоит ровно на 180 у всех |
| искры целиком | примерно у каждого шестого ролика их нет вовсе |
| раскладка превью | три варианта, выбирается по seed |
| темп, зерно, виньетка | выпадают из диапазонов, разные у каждого ролика |

**Тип открытия раньше не работал.** Поле `opening` вычислялось,
защищалось от повторов, печаталось в сводку — и нигде не применялось: все
ролики открывались одинаково. Теперь варианты разведены по-настоящему:

- `quick_cuts` — сразу очередь самых коротких кусков, без разгона
- `long_footage` — один установочный кадр на 5–8 секунд, потом перебивка
- `black_card` — открытие из чёрного, кадр проявляется за 1.4 секунды

Ни один из вариантов не сдвигает таймлайн: сдвиг здесь стоил бы
рассинхрона звука на весь ролик.

Записывать ролик в журнал надо **после выкладки**, а не после сборки —
иначе пересобранный десять раз ролик десять раз вытолкнет из списка
недавних настоящие.

## Что починено в стартовом коде

| где | что было |
|---|---|
| `youtube.py` | `norm()` выбрасывал всё, кроме латиницы: на русском сценарии от блока оставались одни пробелы, главы не находились никогда, шаг падал **на любом ролике** — после всего рендера |
| `build.py` | цветокор выбирался по первому кадру группы и красил все двенадцать: при доле генерации в 30% архив и генерация красились вперемешку чужими грейдами. Теперь LUT ложится на каждый вход отдельно |
| `style.py` | прогресс `pos` в `clip()` не был обрезан единицей, а оценка числа кадров занижалась вдвое — замедление к финалу разгонялось втрое против заказанного и кадры упирались в потолок в 22 секунды |
| `build.py` | верхнеуровневое поле `lut` в спецификации молча игнорировалось, читался только `archive_lut` |
| `build.py` | отсутствие подложки роняло сборку на последнем шаге, после сорока минут рендера |
| `build.py` | без стокового видео вступления не было вовсе — ролик открывался статичным кадром |
| `render.py` | `afade` уходил в отрицательное `st` на роликах короче шести секунд |
| `youtube.py` | `thumbnail_at` за концом ролика давал пустой файл и падение PIL на «cannot identify image file» |
| `build.py` | нет проверки, что `.cube` вообще существует: ffmpeg сообщал об этом с заглушенным stderr где-то в середине рендера |
| workflow | этап `material` падал без ключей Pexels и Pixabay, хотя четыре источника из семи открыты |

Плюс `crf`/`preset` вынесены в `style_override`: замер на тестовой сборке дал
9.5 Мбит/с, то есть 2.8 ГБ на тридцать девять минут — мимо лимита GitHub
Releases в 2 ГБ. `build.py` теперь печатает размер и предупреждает.
