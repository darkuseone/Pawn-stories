## 0. Фактический стек — сверка с предположением ТЗ

ТЗ предполагает «тот же класс инструментов, что у Ancient Whispers». Сверка
по коду: предположение верно по составу, но не по деталям, и детали важны.

| Что | Предполагалось в ТЗ | Фактически в коде |
|---|---|---|
| Сборка | FFmpeg | FFmpeg 6.x, чистый CLI, без обёрток (`pipeline/render.py`) |
| Оркестрация | GitHub Actions | `.github/workflows/build.yml`, один job, лимит 330 мин |
| Озвучка | ElevenLabs | `eleven_multilingual_v2`, эндпойнт `/with-timestamps` — приходит **посимвольное выравнивание** (`pipeline/assets.py:111`) |
| Картинки | Grok | xAI `grok-imagine-image` **плюс Magnific** (`flux2pro` / `nano-banana2` / `seedream5pro`), по умолчанию 70% объёма на Magnific (`assets.py:290`) |
| Отбраковка материала | не упомянута | отдельный слой зрения xAI + локальный ярус (`pipeline/vet.py`, 38 КБ) |
| Описание ролика | `jobs/<id>.json` | `jobs/<id>.json` **+ `channel/defaults.json` + `channel/covers.json`**; единственная точка чтения — `jobspec.load_job` |
| Публикационный пакет | `<id>-youtube.md` | `work/<id>/out/youtube.txt` + релиз `final-<job>` на GitHub |
| Текст на экране | — | libass (ASS) для стекла и шортсов, PIL для обложек, drawtext для плашек |
| Веб-рендер | — | **отсутствует полностью**: ни Node, ни npm, ни Remotion, ни Hyperframes |

Дополнительно к ТЗ: в репозитории есть целый **слой редакторских решений**
(`pipeline/editorial/`, 2305 строк) — разбор сценария на нарративные доли,
кривая темпа, 24-осевой вектор стиля, журнал канала и проверка готового
плана на признаки шаблона. Всё считается по тайм-кодам и тексту, **без
единого запроса к модели**. Это существенно меняет часть выводов ниже:
многое из того, что ТЗ просит «предложить», здесь уже стоит, и правильный
ответ — не строить второй такой слой, а достроить недостающее.

### 0.1. Наследие Ancient Whispers — чего искать не нужно

ТЗ требует отдельным списком отметить всё, что скопировано из
ancient-whispers и не подходит по смыслу. Проверено по коду:

- **Веб-компоненты / Hyperframes / kinetic-center-build** — в репозитории
  нет ни одной строки кода, ни одного пакета, ни одной ссылки на такой
  рендер. Упоминания Remotion и HyperFrames есть ровно в трёх местах
  (`shorts.py:31`, `render.py:226`, `type.py:15`) и все три — это
  **обоснование отказа** («почему не Remotion»): два движка рисуют кадр
  браузером и снимают покадрово, два шортса ≈ 3300 кадров через headless
  Chromium. Это запись принятого решения, а не техдолг. **Удалять её
  нельзя**: без неё следующий подход к «а давайте Remotion» начнётся с
  нуля и закончится тем же. Единственное, что стоит поправить, — сделать
  формулировку явной («решение: не используем»), что и сделано в CLAUDE.md.
- **Концовка «как будто уснул» (fade-to-dark / freeze+darken)** — её здесь
  **никогда не было**. Единственное затемнение в коде — `fade=t=in` на
  ПЕРВОЙ группе и только при выпавшем открытии `black_card`
  (`build.py:join`). Концовки не было вообще никакой: ролик просто
  заканчивался. Это не «лишнее наследие», это **дыра**, и она закрыта — см.
  раздел 2.3.
- **LUT `aegean_teal` / `archive_platinum`** — таких файлов в репозитории
  нет. Фактический пул: `warm_amber`, `copper_dusk`, `dust_gold`,
  `lamp_glow`, `oak_brass` (тёплая семья) и `archive_sepia`,
  `archive_paper`, `archive_silver` (архивный). Палитра уже тёплая и уже
  тематическая. Адаптировать нечего.
- **Что действительно осталось чужим** — одно: плашки с суммами набирались
  системным **DejaVu Serif**, а не шрифтом канала Oswald. Канал свёл
  обложки, стекло названия и шортсы к одному файлу (`type.py`, коммит
  `6ff1edc`), а плашки в этот свод не попали. Исправлено, см. 2.5.

Вывод по Части 0: **пересечений с ancient-whispers, которые нужно
вычищать, практически нет**. Опасность ТЗ описывало верно, но она здесь не
реализовалась — за одним исключением (шрифт плашек).

## 1. Аудит текущей сборки

### 1.1. Как устроен рендер

Полный прогон (`stage: auto`) идёт пятью этапами; всё, что стоит денег,
живёт на этапе 1 и кэшируется:

```
этап 0  material   добор футажа и архива + отбраковка (без озвучки)
этап 1  assets     ОЗВУЧКА + ГЕНЕРАЦИЯ КАРТИНОК + скачивание        ← деньги
этап 2  build      монтаж ffmpeg                                     ← время
этап 3  covers     две обложки (xAI)                                 ← деньги
этап 4  youtube    youtube.txt, главы, теги
этап 5  shorts     два шортса из готового final.mp4                  ← бесплатно
```

Монтаж (`build.py:main`) внутри себя:

1. `plan_shots()` — раскладка материала по таймлайну. Границы кадров — это
   **концы предложений из тайм-кодов ElevenLabs**, а не секундомер.
2. `chapter_boundaries()` + `insert_chapter_cards()` — пауза 2.6 с перед
   каждой новой историей, с настоящей тишиной в звуке
   (`voice_with_pauses`), а не наплывом поверх.
3. `render_one()` — каждый кадр отдельным файлом, **параллельно по числу
   ядер** (`ThreadPoolExecutor(max_workers=cores())`).
4. `join()` — группы по 12 кадров: `lut3d` на каждый вход **до** склейки,
   `xfade` между кадрами, плёночная база, слой искр `blend=screen`, зерно,
   виньетка, плашки `drawtext`. Одна группа — один `filter_complex`.
5. `concat_segments()` — сшивка групп **без перекодирования** (`-c copy`).
6. `burn_ass()` — второй проход ASS по всему ролику (стекло названия).
7. `build_audio()` + `mux()` — голос, подложка, ямы под подложку, сведение.

Титры и названия глав: **есть**. Название выпуска — стекло 0–4.6 с поверх
уже смонтированных кадров (`type.write_opening_ass`), карточка главы —
отдельный кадр-`card` внутри паузы (`render.render_card`). Оба одним
шрифтом канала, кегль 132.

Переходы между сценами: `xfade` из пула в 12 штук, длительность
0.8–1.4 с, жребий разведён с последними роликами через журнал канала
(`channel/log.json`).

### 1.3. Хрупкие места — силентфейлы класса «деньги уже потрачены»

ТЗ просит искать аналоги инцидента `dead-internet-01` (невалидные ключи
JSON, которые никто не проверяет). **Найден живой экземпляр ровно того же
класса, и он именно про `similarity` vs `similarity_boost`:**

```
pipeline/assets.py (было):   vs.get("similarity", 0.78)
jobs/pawn-02.json:           "voice_settings": {"similarity_boost": 0.75}
jobs/pawn-01.json:           "voice_settings": {"similarity_boost": 0.78}
jobs/auction-test.json:      "voice_settings": {"similarity_boost": 0.8}
jobs/auction-01.example.json:"voice_settings": {"similarity_boost": 0.8}
```

`similarity_boost` — имя **из документации ElevenLabs**, его подставляет
любой пример; канал же читал только `similarity`. Четыре спецификации
озвучены на умолчании 0.78 вместо заказанного. Ошибка молчаливая: деньги
списаны, в логе ни строки, на слух разница в similarity почти не
ловится.

| любая опечатка в поле **верхнего уровня** спецификации (`image_prompt` вместо `image_prompts`, `fill_limits`, `vet_visio`) | поле просто никто не читает; ролик собирается на умолчании | закрытый список `jobspec.KNOWN_TOP_LEVEL`, проверка роняет прогон **[СДЕЛАНО]** |

### 1.4. Аудит стоимости и токенов

Где деньги уходят на самом деле:

| Статья | Когда тратится | Сколько | Кэшируется |
|---|---|---|---|
| ElevenLabs TTS | этап 1 | ~21 000 символов на 22-минутный ролик | да, `voice/block_NN.mp3+json` |
| Генерация картинок (xAI + Magnific) | этап 1 | по `image_prompts`, доля Magnific 70% | да, `_batch.json` / файлы |
| Зрение отбраковки (xAI) | этапы 0/1 | десятки кадров × ~центы, сумма печатается в лог по полю `usage` | **нет — было** |
| Обложки (xAI) | этап 3 | 2 генерации | нет (и правильно: `stage: shorts` их не трогает) |
| Разбор сценария, темп, вектор стиля, план, монтажный лист | каждая пересборка | **ноль** — ни одного запроса к модели | — |

**Конкретные места, где сокращение даёт наибольший эффект** (по убыванию):

1. **Повторное зрение на пересборках — устранено. [СДЕЛАНО]**
   Правило канала звучит как «зрение обязано отработать заново, когда
   изменились запросы, промпт отбраковки или состав скачанного» — а код
   спрашивал заново **всегда**. Теперь у каждого вердикта зрения есть
   подпись `sha1(dHash кадра | тема | описание | модель)`. Совпала —
   вердикт берётся из прошлого `vetted.json` и токены не тратятся; не
   совпала (новый файл, другой промпт, другая модель) — спрашиваем, как
   раньше. Экономия: **весь бюджет зрения на каждой пересборке, где
   материал и промпт не менялись**, то есть на четырёх-девяти прогонах из
   пяти-десяти. Лог честно печатает «память зрения: N вердиктов взяты с
   прошлого прогона».
2. **Генерация картинок: доля снижена с 30% до 20% экранного времени.
   [СДЕЛАНО]** Это одновременно и пункт 5.3 ТЗ (реалистичность), и прямая
   экономия: `assets.py` считает число промптов от `generated_share`.
3. **Промпты обложек не дублируются по спецификациям. [было]** Блок правил
   CTR лежит в `channel/covers.json` и дописывается в `art_prompts()`.
   Теперь туда же уехал и сам сюжетный шаблон — см. 4.
4. **Детерминированные шаги вместо модели — уже сделано и это главная
   экономия проекта.** Разбор долей, темп, вектор стиля, выбор подложки,
   эффекты, плашки, монтажный лист, главы YouTube — всё считается кодом.
   Ничего из этого **нельзя** отдавать модели: пересборок у ролика
   пять-десять.
5. **[ПЛАН] Слить два вызова зрения в один запрос на пакет кадров.**
   Сейчас `ask_vision` идёт по кадру (`WORKERS` параллельно). Пакет из
   4–6 кадров в одном запросе экономит входные токены системной части
   промпта. Сложность средняя, выигрыш — десятки процентов от уже
   небольшой суммы. Делать только после п. 1, эффект от которого больше.

### 1.5. Подбор материала под смысл сцены

Не «плоский рандом» и не теги. Устроено так (`build.ShotPicker.score`):

- слова файла берутся из пары (префикс, номер) через манифест запросов
  (`keywords_for`), слова сцены — из текста предложения минус стоп-слова;
- ключ сортировки: **`over_cap` первым** (файл, показанный 3 раза, уступает
  любому непоказанному), затем «не такой же, как предыдущий кадр», затем
  совпадение слов, гашение от числа показов, затем жребий;
- потолки: `MAX_CLIP_REPEATS = 3`, `MAX_IMAGE_REPEATS = 3`.

Замер на ff-ep08 (синтетика): генерация — 62% кадров подобраны по смыслу,
архив и сток — 0%, потому что у 67 файлов нет записи в манифесте. То есть
механизм рабочий, а **данных ему не хватает** — см. [ПЛАН] в 1.3.

Доля реального футажа против генерации: замер печатается в лог каждым
прогоном (`material_report`). На ff-ep08 — генерация 29.8% экранного
времени при заказанных 30%. После правки умолчания цель — 20%, см. 5.3.

## 2. Удержание в основном видео

### 2.1. Открытие: крючок в первые 5–10 секунд

**Что уже есть.** Вектор стиля бросает одно из шести открытий
(`opening_plan`): `long_establish`, `quick_cuts`, `cold_open`,
`slow_reveal`, `hard_in`, `black_card`. Три из шести (`quick_cuts`,
`cold_open`, `hard_in`) — это и есть «самый динамичный видеоряд с первых
секунд»: шаг склейки ужимается до 0.30–0.45 от обычного. Ни один вариант
не двигает таймлайн.

**Чего не было.** Никто не проверял **сценарий**. Монтаж может частить
сколько угодно — если в первых десяти секундах не звучит сумма, частить
не над чем. Проверка по семи боевым спецификациям:

| Ролик | Первые ~10 с | Вердикт |
|---|---|---|
| ff-ep05 chamberlain-jacket | цена есть | OK |
| ff-ep07 kid-icarus | «almost sold it for two hundred dollars» | OK |
| ff-ep08 1943-penny | «worth more than the drawer, the house» | OK |
| pawn-02 | цена есть | OK |
| ff-ep03 | цена есть, но позже 10 с | заметка |
| ff-ep06 nineties-fortunes | «standing knee-deep in mud… looking for a hammer» | заметка |
| **da-vinci-lost-millions** | «On the morning of August twenty-first nineteen eleven…» — дата, не цена | **внимание** |
| **garage-sale-ming-durer-faberge** | разгон | **внимание** |

**[СДЕЛАНО]** В `rails.py` добавлена проверка `_check_cold_open`. Она
смотрит первые 170 символов первого блока (≈10 с при темпе 16 символов в
секунду, замеренном по тайм-кодам ElevenLabs) и ищет **цену или обещание
цены**: `$ £ €`, `dollar/cent/penny/pound`, `thousand/million/billion`,
`worth`, `sold for`, `paid`, `fortune`, `valued`, `appraised` — либо голую
цифру, **кроме четырёхзначной** (год «1943» в первой фразе про монету —
это имя предмета, а не его цена). Нет в первых 10 с, но есть в первых
30 — «заметка»; нет и там — «внимание».

Механизм ровно тот же, что у всего `rails.py`: **ничего не чинит и ничего
не роняет**. Автоправка сценария под метрику дала бы сценарий,
оптимизированный под метрику. Проверка называет то, что иначе видно по
графику удержания через неделю.

Сложность: низкая. Стоимость рендера: ноль (текст, до озвучки).

### 2.2. Карточка названия видео

**Уже было и работает**: `type.write_opening_ass` — стекло 0–4.6 с, fade
in 0.30 / fade out 0.55, кегль 132 подбирается замером под ширину кадра,
шрифт канала Oswald Bold, три слоя (свечение `\blur18` / кант / заливка).
Поверх уже смонтированных кадров, **без новой тишины в начале** — крючок
озвучки не режется.

ТЗ просит «паузу диктора 1.5–2 с на 3–7 секунде». Здесь принято
**осознанно другое решение**, и менять его не стоит: пауза в первые секунды
— это пауза ровно в том месте, где зритель решает, смотреть ли дальше.
Наплыв стекла поверх звучащего крючка даёт то же читаемое название и не
отнимает две секунды у самого дорогого куска ролика. Паузы в 2.6 с в
конвейере есть — но перед **главами**, где они уместны (`CHAPTER_PAUSE`).

**[НЕ НАДО]** переносить сюда паузу диктора. Если всё же нужно — это
однострочная правка в `build.main` (вставить границу `0.0` в `boundaries`),
но она стоит 2 секунды удержания на самом чувствительном месте.

### 2.3. Концовка

**Чего не было.** Ролик просто кончался последним кадром. Ни рекапа, ни
призыва. Три варианта:

| Вариант | Механизм | Стоимость рендера | Минусы |
|---|---|---|---|
| **A. Рекап суммы + призыв поверх последних кадров** (выбран) | события ASS в том же файле, что название выпуска; тот же проход `burn_ass` | **ноль** — проход уже оплачен | не «эффектно», это надпись, а не сцена |
| B. Стоп-кадр находки + сумма крупно | `_freeze_frame` последнего кадра + отдельный клип + пересшивка | +1 кадр-рендер и пересшивка concat, ~секунды | ломает ритм: после движения экран встаёт |
| C. Отдельная монтажная концовка (сетка кадров ролика, «смотри дальше») | новый проход рендера + вторая раскладка | минуты на ролик, плюс код | дорого, и на канале без ведущего выглядит как заставка телеканала |

**[СДЕЛАНО] Вариант A.** `type.outro_lines` + `write_overlay_ass`: за
5 секунд до конца (минус 0.4 с хвоста) на кадр ложится стекло с
`youtube.cover_sub` — той самой суммой, что стоит на обложке, — и второй
строкой поменьше призыв из `channel/defaults.json` → `outro_cta`
(«More impossible finds every week»). Пустая строка = карточки нет.

Рекап берётся из `cover_sub` **только если в нём есть цифра или знак
валюты**. Когда полей `cover_kicker`/`cover_sub` в спецификации нет, они
собираются из заголовка механически — у `pawn-01` так выходит «THE BACK
FIRST», и в концовке это читалось бы как обрывок фразы, а не как итог.
Рекап без цифры не рекап; в таком случае остаётся только призыв. Явное
переопределение — `youtube.outro_recap`.

Это **не** «fade как будто уснул»: картинка не гаснет, движение
продолжается, надпись ложится поверх. Приём сонного документального
формата сюда не перенесён — и не был перенесён никогда.

Сложность: низкая (готово). Риск по производительности: отсутствует.

### 2.5. Сквозные текстовые акценты (side call-outs)

**Уже было, и реализовано близко к тому, что просит ТЗ**
(`editorial/textcard.py`, 380 строк):

- Текст акцента — **не копия субтитра**, а выжимка: из предложения
  вытаскивается числовая фраза и сворачивается («one thousand four hundred
  and twenty-seven gold coins» → `1,427 COINS`, «43,000,000» →
  `43 MILLION`). Словесные числительные разбираются разрядным парсером.
- Позиция — три раскладки (`lower_left`, `lower_right`, `upper_left`),
  жребий на каждую плашку, чтобы не выстраивались в столбик. Нижние
  стоят на 0.760 высоты — **выше зоны, где YouTube рисует интерфейс**.
- Анимация — четыре механики: `stamp` (удар), `slide_up`, **`typewriter`
  (посимвольное появление слоями drawtext)**, `underline_wipe` (линия
  уезжает под текстом). Ось `text_style` вектора стиля; у части роликов
  выпадает `none`, и плашек нет вовсе — приём, стоящий в каждой загрузке,
  перестаёт быть приёмом.
- Привязка к таймкодам — из `marks` через доли (`beats`), отдельного поля
  в JSON **заводить не нужно** и не стоит: ручная разметка «`_акценты`» в
  спецификации разъедется с озвучкой при первой же правке сценария.
- Плотность — ось `text_density`, минимальный зазор `MIN_GAP = 45 с`,
  только на долях `revelation` и `escalation`.

**Что было не так и исправлено [СДЕЛАНО]:**

1. **Шрифт.** Плашки набирались DejaVu Serif Bold — единственная надпись
   ролика не шрифтом канала. Теперь `textcard.font_path()` спрашивает
   `type.font_path()` (Oswald Bold), системные остаются запасными.
2. **Цвет.** Был белый. Теперь тёплый янтарь `0xFFC440` — тот же, что у
   подсветки субтитра (раздел 2.6). Плашка на числе и подсвеченное слово —
   это **один приём канала**, разными цветами они читаются как два разных
   оформления.
3. **Ширина подчёркивания** в стиле `underline_wipe` считалась как
   «символов × 0.62 кегля». Множитель подбирался под DejaVu; Oswald
   заметно уже, и линия вышла бы в полтора раза длиннее надписи. Теперь
   ширина **замеряется настоящим шрифтом** через PIL.

**Стоимость рендера.** Плашки — это `drawtext` внутри уже существующего
`filter_complex` группы склейки, отдельного прохода нет. Дороже всех
`typewriter`: строка печатается слоями, по слою на символ, до 22 слоёв на
плашку. На 15–20-минутном ролике плашек выходит 4–8 штук (зазор 45 с,
только развязки, ещё и жребий по плотности) — это **десятки лишних
`drawtext` на весь ролик**, доли процента времени рендера. Мерить нечего.

**Сколько акцентов оправдано:** текущие 4–8 на 20 минут — верхняя разумная
граница. Больше превращает ролик в инфографику; механизм прореживания уже
стоит и трогать его не нужно.

### 2.6. Вшитые субтитры караоке-стиля — Часть 2.5 ТЗ

Это самый крупный новый кусок. Разберу по порядку, потому что здесь
обнаружилась вещь, которая меняет ответ на вопрос «можно ли вообще».

**Находка.** ElevenLabs отдаёт **посимвольное выравнивание**
(`character_start_times_seconds`), и оно уже оплачено вместе со звуком и
лежит в кэше (`work/<id>/assets/voice/block_NN.json`). До сих пор из него
брались только **границы предложений**, а сами символы выбрасывались.
Поэтому в `shorts.py` стоит честное признание:

> «его тайм-код внутри предложения не измерен, а посчитан пропорционально
> длине слова — на быстрой речи подпись заметно отстаёт от голоса, это
> увидели на готовом шортсе»

Это было верно **только потому, что замер выбрасывался**. Слова можно
достать из того же файла, бесплатно, задним числом.

**[СДЕЛАНО] Что сделано:**

1. `assets.words_between()` — измеренные тайм-коды слов из посимвольного
   выравнивания; кладутся рядом с предложением в `marks.json` (поле
   `words`). Стоит ноль, на пересборке тоже ноль: посимвольные файлы
   приезжают из кэша вместе с mp3.
2. `build.shift_marks()` сдвигает слова вместе с предложением — иначе
   после первой же паузы главы подсветка уехала бы от голоса на её длину.
   `marks_final.json` (он уходит в релиз) теперь несёт слова, и `shorts.py`
   на стадиях `post`/`shorts` получает замер без пересчёта.
3. `type.karaoke_line()` — разметка строки.
4. `type.write_overlay_ass()` — **один файл ASS на название выпуска,
   субтитры и концовку**, и один проход ffmpeg на всё.
5. `shorts.build_ass()` — та же подсветка в шортсе, тем же кодом.

**Механизм подсветки: почему не `\k`.** ТЗ предлагает karaoke-теги `\k`.
Это правильная первая мысль и неверный итог: `\k` красит слово и
**оставляет** его крашеным до конца строки — к концу фразы подсвечено всё,
и подсветка перестаёт показывать, где голос. Нужен противоположный эффект
— бегущее слово. Он делается парой `\t` на каждом слове:

```
{\1c&HFFFFFF&\t(408,498,\1c&H40C4FF&)\t(498,571,\1c&HFFFFFF&)}is
```

цвет уходит в янтарь к началу слова (90 мс) и возвращается в белый к его
концу (140 мс). Тег действует на текст после себя и до следующего блока, а
блок стоит у каждого слова — слова не мешают друг другу. Мягкий переход, а
не мигание, как и просит ТЗ.

**Ответ на вопрос ТЗ «обязателен ли полноценный ASS вместо drawtext»:
да, обязателен, и это зафиксировано.** На `drawtext` перекраска одного
слова внутри уже показанной строки означала бы отдельный слой на каждое
слово с ручным пересчётом координат — десятки фильтров на фразу, и всё
равно без честного переноса строк.

**Перенос длинных строк.** Считается **замером настоящего шрифта**
(`type.measure_width` через PIL), а не числом символов: «illinois» и
«MMMMMMMM» одной длины занимают втрое разную ширину, а одно длинное слово
(«archaeologists», «authentication» — в этом жанре сплошь) переносом не
режется вовсе. Канал уже обжигался на этом в шортсах. Предложение длиннее
двух строк режется на несколько событий **по словам**: у каждого слова
свой измеренный тайм-код, и кусок начинается ровно тогда, когда звучит его
первое слово — синхронизация подсветки при переносе не теряется.

**Геометрия в длинном ролике:** кегль 58, две строки максимум, ширина
строки — 66% кадра (на всю ширину влезает четырнадцать слов, и глаз ведёт
строку дольше, чем звучит фраза), позиция 0.87 высоты — **ниже плашек с
числами** (они на 0.760–0.816) и выше края. Белый Oswald с чёрной обводкой,
без стекла: стекло держит одну короткую надпись в центре, а строка,
живущая весь ролик, на нём мылит картинку.

**Стоимость рендера — ноль.** Ровно потому, что проход `burn_ass` уже
существовал ради названия выпуска. libass рисует хоть одну надпись, хоть
все три за те же деньги. Отдельный проход ради субтитров стоил бы второго
полного перекодирования получасового ролика.

**Выключатель.** `channel/defaults.json` → `burn_subs: true`. `false`
возвращает прежнее поведение («только `subs.srt`, зритель включает сам»).
`subs.srt` пишется в обоих случаях — он всё так же уходит в релиз для
ручной заливки на YouTube.

**Защита от рассинхрона.** Если в `marks.json` нет поля `words` (кэш
старше этой правки), субтитры **не вжигаются вовсе** и в лог уходит
громкая строка. Подпись, гуляющая относительно голоса, хуже отсутствующей.
Лечится любым прогоном `stage: assets` — деньги при этом не тратятся
повторно, блоки берутся из кэша.

Проверено рендером: см. кадры в разделе 7.

## 4. Обложки — промпт-инжиниринг

Структура не тронута: слева белый Oswald Bold (рисует PIL), справа
изображение, `TEXT_ZONE = 0.56`, две штуки, вторая запасная. Текст, как и
раньше, **рисует шрифт, а не модель**.

**Что уже было** (коммит `0fdaae8`): блок правил CTR в
`channel/covers.json` дописывается к **каждому** промпту, включая ручные
`cover_prompts` — один герой на правую половину, расчёт на ~120 px в
мобильной ленте, контраст по яркости, запрет правого нижнего угла (там
шильдик длительности), запрет широкого плана лавки.

**Что добавлено [СДЕЛАНО]:** сам **сюжетный шаблон с плейсхолдерами**
(`scene_template_gap` / `scene_template_scale` в `channel/covers.json`),
который `covers._auto_scenes()` заполняет из темы ролика:

- `{ITEM}` — предмет находки; берётся ранжированием ключевых слов и глав
  (длинное имя вещи бьёт абстракцию вроде «auction records», список
  `skip_keywords` отсекает мусор).
- `{ERA}` — год из темы, заголовка или глав (`period-correct 1943`). Год
  задаёт модели материалы и износ; без него она рисует ровную современную
  студийную съёмку.

Вариант A — «дыра/утаивание» (предмет **отсутствует**, запечатан, спрятан),
вариант B — «масштаб/сделка» (макро предмета или руки-в-перчатках, молоток
крошечным вторым планом).

**Сознательное отклонение от ТЗ: плейсхолдера под сумму в промпте нет.**
ТЗ просит шаблон «с плейсхолдерами под предмет/сумму». Сумму в промпт
класть нельзя: канал уже принял решение, что цифры и буквы на обложке
рисует PIL, потому что модель путает цифры и дописывает лишние нули, — а
блок CTR прямо запрещает модели рисовать любые читаемые знаки. Плейсхолдер,
который модель нарисует неправильно, хуже отсутствующего. Сумма живёт в
`cover_sub` и попадает на обложку отрисовкой.

**Веб-проверка практик** (сентябрь 2026) подтвердила то, что уже зашито в
`channel/covers.json`, и добавила две детали:

- 63% времени просмотра — мобильные; один фокус и жёсткий контраст
  поднимают заметность ощутимо, текста ≤4 слов;
- рекомендуют компоновать с запасом под интерфейс (совет «рисовать
  1280×760, чтобы шильдик длительности не съел важное») — у нас это уже
  закрыто прямым запретом правого нижнего угла и нижней кромки.

Отдельный субагент под это не запускался: правила канала уже написаны, и
поиск нужен был для сверки, а не для сочинения с нуля.

Проверка перед пушем: `python pipeline/covers.py --check jobs/<id>.json` —
печатает kicker, оба промпта целиком и ловит отсутствие блока CTR,
одинаковые сюжеты и пустой крючок.

**Найдено попутно и это важнее промпта.** Правило канала «крючок 3–5 слов
`cover_kicker` + короткая строка с цифрой `cover_sub`» выполняется у
**двух роликов из шести**: поля есть только у `da-vinci-lost-millions` и
`ff-ep07-kid-icarus-attic`. У `ff-ep03`, `ff-ep05`, `ff-ep06` и `ff-ep08`
их нет вовсе, и крючок собирается из заголовка механически — у ff-ep08
выходит «HE FOUND THIS IN HIS LUNCH MONEY», шесть слов вместо пяти, и
**без суммы**. То есть правило, ради которого писался весь блок CTR, на
четырёх роликах просто не применено.

**[СДЕЛАНО]** `jobspec.check()` печатает заметку (не стоп — бывают ролики
без суммы): «нет `youtube.cover_kicker`» и «в `youtube.cover_sub` нет
числа». Второе теперь бьёт дважды: то же поле уходит в карточку-итог в
конце ролика, и без цифры концовка остаётся без рекапа. Заполнить эти
поля — редакторская работа на пять минут на ролик, и её стоит сделать
до следующей пересборки любого из четырёх.

## 5. Сценарий и удержание

### 5.1. Выжимка по ретеншн-структуре и куда её встроить

Сверка с практикой (сентябрь 2026), коротко и без воды:

- **Cold open без приветствия.** Первая строка — ошибка, результат,
  предупреждение или разрыв любопытства. Уходят на третьей секунде именно
  из-за первой строки.
- **5–15 с — обещание выплаты:** одна конкретная вещь, которую зритель
  получит, если останется.
- **15–30 с — крючок удержания:** информационный разрыв, доказательство
  результата или начало истории. Обещать конкретное и **не выдавать**.
- **Открытая петля закрывается в конце.** Открыл — закрой, иначе концовка
  ломает доверие.

Куда это встроено в конвейере:

| Рекомендация | Где живёт | Статус |
|---|---|---|
| cold open, сумма в первых секундах | `rails._check_cold_open` | **[СДЕЛАНО]** |
| обещание выплаты в 5–15 с | `open_loop.question` + `rails._check_open_loop` (вопрос в первом блоке) | было |
| выплата придержана | `open_loop.payoff_block` ≥ середины, проверяется | было |
| петля закрывается в конце | карточка-итог с суммой, раздел 2.3 | **[СДЕЛАНО]** |
| «быстрый факт сразу» как **требование к промпту генерации сценария** | — | **[ПЛАН]**, см. ниже |

**[ПЛАН] по п. 5.5 ТЗ.** Промпта генерации сценария в этом репозитории
**нет**: сценарии пишутся снаружи и приезжают готовыми в `script_blocks`.
Поэтому «зафиксировать в промпте» здесь физически некуда — фиксировать
надо в двух других местах, и оба дешёвые:

1. в `docs/ЗАДАНИЕ-аукционный-канал.md` (правила написания сценария) —
   отдельный абзац «первые две фразы: сумма или обещание суммы»;
2. в `rails._check_cold_open` — уже сделано, механическая проверка того же
   правила.

Второе важнее первого: правило в документе никто не читает, а строка
«[внимание] ХОЛОДНОЕ_ОТКРЫТИЕ» в логе сборки видна каждый раз.

### 5.2. Переструктурирование существующих сценариев

Проверка (таблица в 2.1) нашла два ролика с разгонным вступлением:
`da-vinci-lost-millions` и `garage-sale-millions-ming-durer-faberge`. Оба
уже собраны и выложены; переписывать их означает переозвучку, то есть
новые деньги. **[ПЛАН]**: правило применять к новым, старые не трогать —
кроме случая, когда ролик всё равно идёт на пересборку по другой причине.

### 5.3. Доля реального материала — 80/20

**[СДЕЛАНО]** `channel/defaults.json` → `style_override.generated_share`
снижена с `0.30` на `0.20`.

Что это меняет:

- `assets.py` считает число промптов генерации от этой доли — значит
  **меньше платных генераций**;
- `build.MaterialMix` держит пропорцию по экранному времени, а
  `material_report` печатает замер и предупреждает, если генерация полезла
  за свои проценты.

**Важная оговорка, которую нельзя обойти умолчанием.** Семь существующих
спецификаций задают `generated_share` **у себя** (0.30–0.35), и
спецификация выигрывает. Новое значение получат новые ролики. Это
сознательно: снижение доли генерации на уже собранном ролике означает, что
недостающие 10% экранного времени должен закрыть реальный материал,
которого в кэше может не быть, — и план честно уедет обратно наверх с
предупреждением в логе. Правильный порядок — `stage: material` с более
широкими `archive_queries`, **потом** снижение доли в спецификации.

Напоминание из CLAUDE.md, которое тут работает в плюс: у стока просить то,
что снимают много и при свете; конкретику (имена, места, годы) — у
архивов; сцены, которых не существует в природе (пустой зал суда, стойки
секонд-хенда, сама сцена находки) — у генерации. Именно эти 20% и есть
законное место генерации.

### 5.4. Настройки голоса

Фактические значения по спецификациям: `stability` 0.33–0.46, `similarity`
0.72–0.78 (плюс четыре файла с нечитаемым `similarity_boost`), `style`
0.12–0.35. То есть настройки **разъехались** ровно так, как когда-то
разъехались наборы эффектов, — потому что лежали в семи копиях.

**[СДЕЛАНО]** Умолчание канала заведено в `channel/defaults.json`:

```json
"voice_settings": { "stability": 0.36, "similarity": 0.74, "style": 0.28 }
```

Обоснование диапазонов (не гарантия — именно обоснование):

- **`stability` 0.32–0.40.** Ниже 0.30 ElevenLabs начинает «играть» и на
  длинной начитке даёт скачки интонации между блоками, которые слышны на
  склейке. Выше 0.45 — ровная документальная подача, та самая
  «убаюкивающая», от которой канал уходит. 0.36 — середина рабочего окна.
- **`style` 0.25–0.35.** Это прямая ручка выразительности, и именно её
  надо поднимать под азарт. Выше 0.40 на многих голосах появляется
  театральность и «продажный» тон, который в жанре «реальная история»
  читается как фальшь. Было 0.10–0.20 у большинства роликов — это подача
  Ancient Whispers, а не этого канала.
- **`similarity` 0.72–0.78.** Трогать не нужно: это близость к исходному
  голосу, а голос менять не просили. 0.74 — как у большинства.

**Это нужно прогнать и сравнить на слух, а не принимать на веру.**
Дешёвый способ: один блок, два прогона с разными настройками — `stage:
assets` на копии спецификации с другим `id`. Голос переозвучивается только
для блоков, у которых нет пары mp3+json в кэше.

Отдельно: **`similarity_boost` теперь читается наравне с `similarity`**, и
несовпадение имён больше не молчит — `jobspec.check` печатает заметку.

### 5.5. «Быстрый факт сразу» как обязательный элемент

См. 5.1: механическая проверка сделана, место для текстового правила
названо. Дублировать правило в третьем месте не нужно.

следить, чтобы журнал заполнялся после каждой выкладки, иначе разведение
работает вхолостую.

## 7. Что проверено и как

Всё ниже прогнано локально на синтетике (`pipeline/mock.py`), с настоящим
ffmpeg 6.1 и настоящим шрифтом канала. Денег не потрачено.

```
python pipeline/smoke.py jobs/ff-ep08-1943-copper-penny.json   → ПРОЙДЕН
python pipeline/covers.py --check jobs/<id>.json               → все спеки
python pipeline/build.py jobs/pawn-01.json                     → полный монтаж
```

Новые ворота в смоуке:

- имена полей спецификации, цветокоры, `voice_settings` — до денег;
- холодное открытие — печатается вердикт по первому блоку;
- `overlay.ass`: есть субтитры, есть янтарная подсветка, **число полей в
  каждой строке `Style` совпадает с `Format`** (лишнее поле libass читает
  молча и не тем ключом), **нет ни одной анимации `\t(a,b)` с концом
  раньше начала** (такие libass молча не рисует — поймано в разработке);
- плашки набираются шрифтом канала и в фирменном янтаре;
- подсветка звучащего слова в шортсе — тот же код, что в длинном;
- `karaoke_ready` не принимает предложение без измеренных слов.

**Полный монтаж `pawn-01` (2.5 мин) прошёл до конца, exit 0:**

```
── надписи одним проходом ASS: название «WHY DEALERS ALWAYS LOOK AT»,
   субтитры с подсветкой, итог …
── финал
  видео 150.767 с, звук 150.748 с, тайм-коды 150.767 с
```

— то есть звук и картинка сошлись (расхождение 19 мс при пороге 500 мс),
паузы глав врезаны, субтитры вожжены, карточка-итог на месте. Доля
генерации по замеру — ровно 20.0%, как и заказано новым умолчанием.

Кадры из ЭТОГО файла проверены глазами: на 20-й секунде строка субтитра
белая, слово `handling` янтарное ровно на своём тайм-коде; на 2-й секунде
стекло названия; на 148-й — карточка-итог с призывом.

Рендером проверено глазами (кадры снимались из тестовых mp4):

- субтитр длинного ролика: строка целиком белая, слово `sitting` — янтарное
  ровно на своём тайм-коде;
- шортс 1080×1920: шапка с вопросом сверху, субтитр снизу, подсвечено
  `million.` на своём тайм-коде, `7` уже отпущено в белый;
- плашка `$9,000 SOLD` — Oswald Bold, янтарь, на своём месте кадра;
- карточка названия выпуска — стекло, Oswald, перенос по замеру.

## 8. Что осталось несделанным сознательно

1. **Пауза диктора под карточку названия** (2.2) — стоит 2 секунды на
   самом дорогом куске ролика. Нужна — одна строка, но это редакторское
   решение, а не техническое.
2. **Отдельный рендер шортсов с собственным ритмом** (3.3) — полный проход
   ещё двух роликов на каждую пересборку.
3. **Переписывание сценариев da-vinci и garage-sale** (5.2) — переозвучка.
4. **Ручное поле `_акценты` в спецификации** (2.5) — разъедется с озвучкой
   при первой правке сценария; автоматический разбор по числам надёжнее.
5. **Плейсхолдер суммы в промпте обложки** (4) — модель путает цифры,
   правило канала прямо запрещает читаемые знаки на генерации.
6. **Эпизодные проверки в `smoke.py`** — там лежат условия, прибитые к
   конкретным `id` (`da-vinci-lost-millions`, `ff-ep07-kid-icarus-attic`).
   Это общий шлюз, и он будет расти на каждый ролик. **[ПЛАН]** вынести
   такие ожидания в сам `jobs/<id>.json` (блок `_ожидания`), а в смоуке
   оставить обход. Не трогал: правка механическая, но задевает чужие
   проверки, и её лучше делать отдельным коммитом.
