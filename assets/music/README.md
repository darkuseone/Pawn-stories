# Музыкальные подложки

Здесь лежат подложки канала: `bed1.mp3` … `bed5.mp3`.

## Как выбирается подложка

Не одна на канал, а **жребием на каждый ролик** — как цветокор и основной
переход. Правила те же:

- Пул читается **с диска**: любой `*.mp3` в этой папке участвует в жребии.
  Добавить шестую подложку — просто положить файл, править код не нужно.
- Жребий **воспроизводим**: seed из `id` ролика. Один и тот же ролик при
  пересборке получит ту же музыку.
- Две последние подложки канала **не повторяются** (`channel.py`, `DEPTH`).
  Пять файлов при глубине 2 — выбор всегда есть.

Жребий подложки идёт ОТДЕЛЬНОЙ лентой случайных чисел, а не общей лентой
движка стиля. Это не чистоплюйство: лишний вызов в общей ленте сдвинул бы
все последующие, и у каждого уже собранного ролика при пересборке
поменялись бы цветокор, переход и движения камеры.

Выбранная подложка пишется в журнал канала (`channel/log.json`, поле
`music`) и в монтажный лист рядом с роликом.

## Когда нужна конкретная дорожка

Поле `music` в спецификации ролика — жёсткое переопределение, жребий тогда
не бросается вовсе:

```json
"music": "assets/music/bed3.mp3",
"bed_gain_db": -26.0
```

Штатно это поле пустое. Если указанного файла не окажется (например,
дорожку переименовали), сборка не упадёт и не соберётся молча без музыки:
в лог уйдёт предупреждение, а подложка возьмётся жребием.

`bed_gain_db` — насколько подложка тише голоса. Чем меньше число, тем тише.
−26 дБ это фон, который слышно, но который не спорит с речью. Подложка
дополнительно приседает под голосом в ключевых местах — где именно, решает
`duck_style` в векторе стиля.

Длина дорожки любая: подложка зацикливается на весь ролик, заход и уход
сглаживаются автоматически (`render.build_audio`).

## Если подложек нет вовсе

Сборка не падает. `build.py` пишет в лог

```
! подложек нет в assets/music — собираю только с голосом
```

и собирает ролик с одной начиткой. Голос при этом всё равно проходит
нормализацию до −16 LUFS, так что тестовые сборки звучат так же ровно, как
готовые.
